# FR-232: Widget identity widgetGuid minted at embed-code creation

**Repo:** SimonBarnett/a-search
**Phase:** 5d - ComponentsPiece
**Issue:** #1346
**Supersedes:** FR-211 (#1199) uri-slug as storage key

## Decision (LOCKED)

Every widget gets a server-minted lowercase RFC 4122 UUID (`widgetGuid`) when its embed code is created. HOST remains the customer key; GUID replaces URI folders under `{env}/x/{customerNumber}/{widgetGuid}/`.

### Rules

1. **Format.** v4 at mint; v5 accepted for migrated folders. Invalid -> 400 `invalid_widget_guid`.
2. **Mint.** `POST /widgets` mints via CSPRNG; clients never generate GUIDs. Response 201: `{ widgetGuid, layout, snippet }`.
3. **Registry.** `dbo.Widgets` in a_search only (FR-251). One host -> many widgetGuids.
4. **Snippet.** `data-widget-guid` + `data-mode`; no host in the snippet (runtime `location.host`).
5. **Bind.** Extension with `host` binds at mint. Copy-page binds on first `GET /parts`. Other host -> 403 `widget_host_mismatch`.
6. **Paths.** Only `shared/widgets/widgetPath.js` builds keys (`assertWidgetGuid`).
7. **API.** `GET /parts` and `GET /go` require `widgetGuid` (missing -> 400 `widget_guid_required`). Optional `uri` is diagnostics only.
8. **Migration.** `scripts/migrate-uri-to-guid.js` (`--dry-run` default; `--apply` moves). Deterministic UUID v5 of `{host}\n{uri-slug}`.
