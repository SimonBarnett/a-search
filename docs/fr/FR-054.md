# FR-054: Persist local S3 mapping service

## Goal
Provide a durable service that persists the local↔S3 mapping used by search
results and the performance endpoint (link/token/click paths to S3 keys and
related metadata).

## Deliverables
- `shared/mapping/` or `services/s3-mapping/` with upsert/get/list APIs
- Store mapping records: `{ env, userId, source, catalogId?, tokenOrClickRef,
  s3Key, searchId?, createdAt, meta }`
- Backing store LOCKED in PR: MSSQL table **or** S3 inventory JSON under
  `{env}/_mapping/{userId}/...` (prefer MSSQL if performance queries need joins)
- Writers: search result write path registers mapping; click ingest updates it
- Readers: performance endpoint (FR-053) uses mapping to attach link stats
- `.env.example` + docs `docs/s3-mapping.md`

## Testable
- Upsert then get returns same key; list by userId
- Isolation: live vs sandbox prefixes/rows never mix
- Fail-when: mapping only ephemeral in Lambda memory

## Out of scope
- Full clickstream warehouse / Athena
