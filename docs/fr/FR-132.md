# FR-132: Stage awin/impact onboarding Lambda assets to include shared/

**Repo:** SimonBarnett/a-search  
**Phase:** 3 - AWS installable release  
**Shape:** service (unchanged)

## Goal
Onboarding Lambdas currently zip only `onboarding/src` but require `shared/identity/userId` (and related). Stage assets with `shared/` so handlers work in AWS.

## Deliverables
- `scripts/stage-onboarding-lambda-asset.js` (or parameterized)
- CDK awin+impact live/sandbox use staged assets
- Pin tests for shared/identity presence

## Testable
- Pin + synth exit 0

## Out of scope
- FR-125 live HTTP drain behaviour

## Decision (implement)

Stage awin + impact onboarding Lambda assets the same way FR-444 stages
provider workers: `scripts/stage-onboarding-lambda-asset.js` copies
`providers/local/<id>/onboarding/src/**` and `shared/**` into
`cdk/onboarding-lambda-asset/<id>/`, preserving the five-level relative
`require('../../../../../shared/identity/userId')` from `emitSignupRow.js`
/ `createMerchantUser.js`.

CDK (`ASearchStack`) uses `stageOnboardingLambdaAsset` +
`onboardingHandlerPath` for all four functions (awin/impact × live/sandbox).
Handler strings are
`providers/local/<id>/onboarding/src/handler.handler` (posix). FR-056a–d
pins stay on function names + `A_SEARCH_ENV`; they do not hard-pin
`handler.handler`.

Pins: `tests/fr132-stage-onboarding-shared.test.js` (asset layout + CDK
source + synth Handler values).
