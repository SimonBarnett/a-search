# FR-221: Embed snippet self-configures from placement host

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged; wizard/pages are delivery)
**Issue:** #1226

## Goal
Copied widget code does not embed host; at runtime the widget reads
`location.host`. Widget identity is `data-widget-guid` (FR-232); pathname is
diagnostics only.

## Decision (LOCKED)

- Shared snippet template (`shared/widgets/snippet.js` / FR-232 rule 4):
  `data-widget-guid` + `data-mode` only -- **no** `host=` query default and
  **no** `data-host` in the pasted markup.
- Runtime (`shared/widgets/placement.js` + `widget/a-search-widget.js`):
  `host` from `location.host` (or `hostname`); `widgetGuid` from
  `data-widget-guid`; `pathname` exposed as `uriDiagnostics` only (never the
  storage key).
- Cross-link: Parts paging / layout fetch remains FR-201; this FR pins
  self-config only.
- Docs for both public sites: `docs/components-piece-embed.md` (smartcatalogue.uk
  and clubmadeira.uk copy pages paste the same template).
- Out of scope: Parts API implementation.

## Deliverables
- Snippet template without host
- Runtime placement helper + thin widget boot
- Docs on both sites + FR-201 cross-link

## Testable
- Snippet has no `host=` default; contains valid `data-widget-guid`
- Runtime uses `location.host`

## Out of scope
- Parts API
