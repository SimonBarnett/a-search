**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1194
**Amended by:** FR-3344 (#3344) -- replace single `in.json` with `IN/` folder

## Goal
Read normalised inbound search files under IN/, append relevant parts to live.json, delete consumed files. Agent is only writer of live.json.

## Decision (LOCKED)

- Entry: `shared/widgets/agentIngest.js` (`runIngestPass`, `writeInSearchFile`).
- Path: `{root}/{env}/x/{customerNumber}/{widgetGuid}/IN/{searchId}.json` (FR-232 + FR-3344).
- Writers never merge into a single `in.json`. Each search writes its own file via `writeInSearchFile`.
- Safe consume: move ready `IN/*.json` into `IN/.processing/` -> merge -> delete processing files. New files written to `IN/` during a pass remain for their own `in_ready` event.
- Merge skips parts matching `searches.json.exclude[]` (partId or title match).
- Cap on write (#1345): `LIVE_PART_CAP_FREE` = 10 unless fullTier (`upgraded && layout==fullscreen`) then `LIVE_PART_CAP_FULL` = 500.
- Selection inside cap: score descending, then price ascending.
- Re-run with no ready `IN/*.json`: skipped, `live.json` unchanged.
- Agent is the only writer of `live.json` (Parts API reads only).
- Out of scope: prune / top10 roll (FR-207).
