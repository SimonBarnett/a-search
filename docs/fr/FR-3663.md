## Decision (LOCKED)

- `tests/fr2021-ci-queue-starvation.test.js` matches
  `timeout-minutes:[^\n]*\b180\b` so the FR-2611 / #3133 expression
  `timeout-minutes: ${{ needs.classify.outputs.heavy == 'true' && 180 || 5 }}`
  stays green.
- `tests/helpers/runCdkSynth.js` default timeout is `600_000` ms
  (`DEFAULT_SYNTH_TIMEOUT_MS`).
- On timeout, kill the whole process tree (`taskkill /T` on Windows;
  process-group `SIGKILL` on Unix). Never leave an orphan `cdk` holding
  a `cdk.out` lock.
- Each `runCdkSynth` call still uses a private `--output` directory
  (`cdk.out-<pid>-<seq>`, FR #3462).

## Follow-up (#3665 busy-wait fix)

- PR #3665 waited on async child events with a `while (!settled) sleepMs(50)`
  loop (`Atomics.wait`). That blocks the event loop, so `close` never fired:
  every synth ran the full 600s, then failed with ETIMEDOUT.
- `spawnSyncTreeKill` now blocks in a real `spawnSync` of a small node
  supervisor (`runCdkSynth.js --fr3663-supervise`). The supervisor owns the
  timer; on timeout it kills the whole tree while the root is still alive
  (`taskkill /T /F` on Windows; process-group `SIGKILL` plus a descendant
  walk on POSIX, so a `setsid` child cannot escape). Exit code 124 maps to
  `error.code === 'ETIMEDOUT'`.
- `runCdkSynth` removes the `cdk.out-<pid>-<seq>` dirs it allocated at
  process exit (set `A_SEARCH_KEEP_CDK_OUT=1` to keep them).
- Pin: `tests/fr3663-synth-no-busywait.test.js` (real child returns in
  seconds; tiny timeout reports ETIMEDOUT; cdk.out-* cleaned up).
