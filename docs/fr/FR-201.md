# FR-201: Widget JS capture host + widgetGuid page Parts API

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1189

## Goal
Ship embeddable widget JS that boots every `.a-search-widget[data-widget-guid]` on the page, pages `GET /parts?host&widgetGuid&offset&n`, and applies layout from the Parts response (fallback `data-mode`).

## Decision (LOCKED)

- Module path: `widget/a-search-widget.js` (exports `boot`, `mountWidget`, `pageFullscreen`).
- Selector: `.a-search-widget[data-widget-guid]` only (identity is widgetGuid per FR-232; not URI).
- `host` from `location.host` (optional `data-host` override for tests).
- `uri` = `location.pathname` sent as optional diagnostics query only (never a key).
- Layout: use Parts API `layout`; fall back to element `data-mode`; default `horizontal`.
- Modes (`horizontal` | `vertical` | `fullscreen`) only change layout attributes / structure; no host theme CSS.
- Idempotent boot: set `data-a-search-booted=1` after first mount; second script paste / `boot()` skips.
- Fullscreen paging: `pageFullscreen` loads `data-next-offset` and appends parts.
- Snippet shape (FR-232 rule 4): empty container + script tag; no hardcoded shop host in the snippet.
- Click `/go` wiring is out of scope (sibling FR).

## Deliverables
- `widget/a-search-widget.js`
- `data-mode` attribute fallback
- Fullscreen paging helper
- Pin tests without jsdom (minimal DOM fixture)

## Testable
- Two containers on one page -> two independent Parts calls and renders
- Pasting the script twice -> no double render
- Modes only change layout
- `docs/fr/FR-201.md` Decision LOCKED ASCII

## Out of scope
- Host theme CSS
- Click go wiring
