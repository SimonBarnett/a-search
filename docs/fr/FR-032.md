# FR-032: Default AWS SQS sendMessage for entry fan-out

## Goal
Production entry fan-out must SendMessage to SQS without requiring every
caller to inject `sendMessage`; tests keep injectable override.

## Deliverables
- `entry/src/sqsSend.js` (or equivalent) using `@aws-sdk/client-sqs`
- Resolve destination URL from registry `queueEnv` + env (see FR-034)
- Wire as default in `fanOutEnqueue` / entry handler when no inject
- `package.json` dependency on AWS SDK v3 SQS client
- `.env.example` documents required queue URL vars (no secrets)

## Testable
- Unit test with mock SQS client: one SendMessage per enabled source; payload
  includes searchId, userId, env, source, queueName
- Injected `sendMessage` still bypasses AWS client (existing fanout tests green)
- Fail-when: default path is still `async () => {}` with no client module

## Out of scope
- Creating queues in CDK (FR-036); API Gateway (FR-035)
