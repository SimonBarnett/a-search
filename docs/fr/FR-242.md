# FR-242: Squarespace shop connect via Commerce API OAuth (offline refresh)

**Repo:** SimonBarnett/a-search
**Phase:** 5e - Merchant shops
**Issue:** #1356
**Status:** Decision LOCKED

## Goal

"Add shop -> Squarespace" connects a merchant's Squarespace Commerce site, stores
per-shop credentials in the vault, and lets FR-240 download products into
`a_search.dbo.Parts`. Merchant source (no automatic commission).

## Decision (LOCKED)

Simon 14:11 / 14:35-14:49 / 15:27 BST (issue updates win).

- Adapter: `shared/shops/adapters/squarespace.js` registered as `squarespace`.
- OAuth authorize:
  `https://login.squarespace.com/api/1/login/oauth/provider/authorize`
  with `client_id`, `redirect_uri`, `scope=website.products.read`, `state`,
  `access_type=offline`.
- Callback exchanges `code` at
  `POST .../oauth/provider/tokens` -> 30m `access_token` + 7d one-time
  `refresh_token`. Vault pointer on Shop; **persist new refresh token before**
  using the new access token.
- Keep-alive: `runSquarespaceKeepAlive` every
  `SQUARESPACE_REFRESH_KEEPALIVE_DAYS` (default 5). Invalid refresh ->
  Shop `suspended(auth)` + reconnect notice stub.
- API key fallback when `SQUARESPACE_API_KEY_FALLBACK=true` (default true until
  OAuth client approved): validate with one Products call; vault
  `authMethod=api_key`; ask reconnect via OAuth later. Never echo the key.
- Provider folder `providers/local/squarespace/` (`kind: local`, stay-dark
  enabled false until ops flips flags). Catalogue:
  `GET /v2/commerce/products` + required User-Agent; cursor pagination;
  normalize variants -> Parts (`Source=squarespace`, `FeedKey=shopId`).
- madeiradb read-only (FR-251). Shops/Parts in `a_search`.
