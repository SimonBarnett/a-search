# FR-228: Email magic link or OTP login path

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged; login is delivery)

## Goal
Enter email only: send magic link or OTP; verified email starts session and maps to identity code.
Merchant signup verifies via **SMS OTP** (E.164 phone).

## Deliverables
- Request-code / verify endpoints: `POST /auth/email/request|verify`, `POST /auth/sms/request|verify`
- Mailer interface stubbable in tests (`shared/notify/mailSender.js`)
- SMS sender interface stubbable in tests (`shared/notify/smsSender.js`)
- Session JWT after verify (`contactVerified: true`)
- `a_search` tables `Merchants` + `OtpCodes` (never madeiradb `SystemOTPs`)
- Merchant Add-shop gate requires contact-verified session

## Testable
- tests/components-piece-auth-email.test.js
- Unverified email/session cannot complete merchant/partner gate (`contact_unverified`)

## Out of scope
- Password reset flows
- Live SNS/Twilio credentials in git
- Partner/club SMS (email path only unless a later FR says otherwise)

## Decision (LOCKED)

- Email path: 6-digit OTP or single-use magic link; 10-minute TTL; hashed secrets only.
- Merchant path: SMS OTP (E.164, UK `+44` default); max 5 verify attempts; max 3 sends / 15 min; 10 / day; 60s resend cooldown.
- Session mint: HS256 JWT with `userId` + `contactVerified: true` + `contactChannel`.
- Storage: `a_search.dbo.OtpCodes` / `Merchants` via migration `011_Merchants_OtpCodes.sql`.
- Gate: `POST /merchant/shops/connect` returns 403 `contact_unverified` without verified contact.
