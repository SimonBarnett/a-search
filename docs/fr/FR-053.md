# FR-053: Performance endpoint (clicks, visits, sales for JWT account)

## Goal
Add a second HTTP endpoint so an agent can query visitor/clicks performance for
the token’s account (`userId` from JWT), as full as practical including actual
sales.

## Deliverables
- Route e.g. `GET /account/performance` or `POST /account/performance` on entry
  (or dedicated `performance/` Lambda behind same API Gateway)
- Auth: Bearer JWT; **only** that claim `userId` (body cannot override — same as search)
- Response includes at least: clicks, visits/unique visitors, conversions/sales
  count, sale amounts, commission amounts, currency breakdown, top links/merchants,
  date range filter (query/body), env live|sandbox
- Read model from MSSQL transactions/click tables and/or S3 mapping service (FR-054)
- Docs: `docs/endpoint-performance.md` + update `a-search-endpoint` skillbook
- Mock: `docs/mocks/performance.html` (key) plus empty/error if UI wireframe required

## Testable
- 401 without JWT; 200 with fixture data scoped to JWT userId
- Another userId in body ignored / 401 on mismatch
- Empty account → 200 with zeros/empty arrays (not 404)
- Fail-when: only search endpoint exists or sales omitted from schema

## Out of scope
- Real-time streaming; non-JWT API keys
