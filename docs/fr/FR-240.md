# FR-240: Shop go-live queues full parts import; weekly refresh via maintainer roll

**Repo:** SimonBarnett/a-search
**Phase:** 5e - Merchant shops
**Issue:** #1354
**Status:** Decision LOCKED

## Goal
When a shop becomes `live` (FR-239), import its catalogue into `a_search.dbo.Parts`
and refresh weekly via the existing maintainer roll. Credentials never travel in
SQS messages.

## Decision (LOCKED)

- Keying: `Parts.Source` = provider id; `Parts.FeedKey` = `shopId`; natural key
  `(Source, FeedKey, MerchantProductId, Env)` unchanged. Product URLs absolute.
- Go-live (paid `subscriptionStatus=active` only; `trialing` unpaid):
  1. Upsert `PartFeedKeys` `{ Kind:"shop", Active:1, Locator:shopDomain, FeedKey:shopId }`.
  2. Enqueue SQS FIFO `a-search-shop-sync.fifo` `{ type:"full", env, shopId, provider }`
     with `MessageGroupId=shopId` and
     `MessageDeduplicationId={shopId}:full:{stripeSubscriptionId}:{liveAt}`.
- Weekly roll selects due `Kind=shop` keys whose Shop is `live` + paid; enqueues
  `{ type:"refresh" }` dedupe `{shopId}:refresh:{yyyy-Www}`; on success
  `NextCheck = now + SHOP_REFRESH_DAYS` (default 7).
- Consumer reads vault via Shop `credentialsSecretRef`, pages provider `catalog.js`,
  staging MERGE + soft-delete missing for that FeedKey, updates Shop sync summary.
- Failures: 401/403 -> `suspended(auth)`, Active=0, reconnect email stub;
  429/5xx -> backoff NextCheck +1h/+4h/+24h; DLQ after 5 receives.
- Stop serving (suspended/cancelled): Active=0 + soft-delete that FeedKey's Parts.
- Unpaid skip (FR-241): enqueue and consumer re-check; `lastSyncResult=skipped_unpaid`.
- Module: `shared/shops/shopSync.js`. Migration: `db/migrations/012_PartFeedKeys_shop_kind.sql`.
- madeiradb read-only (FR-251).
