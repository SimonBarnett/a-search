# FR-203: Widget click via /go never embed affiliate URL

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1191

## Goal
View deal triggers GET /go and opens returned url; part cards do not contain affiliate hrefs.

## Decision (LOCKED)

- Click target: `button[data-action="go"]` inside `.part[data-part]` (no `<a href>` on cards).
- Request: `GET /go?host&widgetGuid&part` using the GUID of the widget that owns the card (FR-232). Optional diagnostic `uri` is not a /go key.
- Response: open `body.url` in a new browsing context (`_blank`, `noopener,noreferrer`) via `openUrl` / `window.open`.
- Markup rule: `partsHtml` never embeds `part.url` / `part.href` and never emits `href=` on cards; destination comes only from /go.
- Bind once per widget root (`data-a-search-go-bound`); delegated click survives fullscreen appends.
- Pin: `tests/components-piece-widget-go.test.js`.

## Deliverables
- Click handler
- open destination new page
- markup without affiliate URLs

## Testable
- Pin: rendered HTML has no http affiliate pattern on cards
- go called with host widgetGuid part

## Out of scope
- DNS implementation details (FR-200)
