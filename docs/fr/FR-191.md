# FR-191: CDK: deploy second-region stack via region+stage context

**Repo:** SimonBarnett/a-search
**Phase:** 4 - post-v0.1 enablement / hardiness
**Shape:** service (unchanged)

## Goal
Allow `cdk deploy` of a second regional stack using context region/stage without renaming source. Function/queue names include region or stage per FR-156 pattern.

## Deliverables
- Context knobs + pin synth for two fake regions in unit test
- deploy.md multi-region section

## Testable
- Synth pin exits 0

## Out of scope
- DNS failover (FR-193)

## Decision (LOCKED)

Deploy a standby regional stack with the same source using CDK context:
- `-c region=<aws-region>` (FR-141; default primary `eu-west-2`)
- `-c stage=<token>` (FR-156 name suffix)
- `-c includeRegionInNames=true` (or `-c regionSuffix=euwest1`) so physical names and stack id include a region token (FR-191)

Example standby:
`npm run deploy -- -c account=ACCOUNT -c region=eu-west-1 -c stage=standby -c includeRegionInNames=true`

Default (no stage / no includeRegionInNames) keeps production names unchanged.
Strategy remains active-passive (FR-190). DNS cutover is FR-193.

Needle: `Decision (LOCKED)` + `includeRegionInNames` / `regionSuffix` + `stage` + `eu-west-2` / standby.
