# FR-208: CDK API Gateway routes for /parts and /go

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1196

## Goal
Expose GET /parts and GET /go on the HTTP API with IAM/lambda wiring; synth clean.

## Decision (LOCKED)

- CDK `HttpApi` routes (all -> entry Lambda):
  - Public (FR-157 stage throttle): `GET /parts`, `GET /go`, `GET /ext/status`, `POST /widgets`, `POST /w/events`
  - JWT (verified in Lambda): `PATCH /widgets/{widgetGuid}`, `POST /widgets/{widgetGuid}/feedback`, `GET /widgets/stats`, `GET /widgets/{widgetGuid}/stats`, `GET /account/commission`, `POST /account/stripe/link`, `POST /account/payouts`, `POST /account/upgrade`
  - Stripe webhook: `POST /webhooks/stripe` (signature check in sibling FR)
- Query identity for /parts and /go: `host&widgetGuid` (FR-232).
- Env knobs via CDK context (no secrets in git): `-c signupUrl=...` -> `A_SEARCH_SIGNUP_URL`; `-c extStatusNegTtlS=...` -> `EXT_STATUS_NEG_TTL_S`.
- CORS allowMethods includes PATCH.
- Handlers for new routes may stub `501 not_implemented` until FR-232 / #1344 / #1345 / FR-234 land.
- Widget-events queue / aggregator / hourly rollup belong to FR-234 CDK (pin when that lands).
- Out of scope: production deploy from Plan.
