# FR #5315

GitHub: https://github.com/SimonBarnett/a-search/issues/5315

## Goal

A catalog `POST /search` (no hostkey/guid) returns **200** when one enabled awsSearch id has no queue URL. That id is left out of `enqueued` and listed in `skipped`. The other enabled ids still enqueue.

## Deliverables

- `entry` fan-out catches `missing_queue_url` per source and continues.
- The 200 body includes `skipped: [{ "id", "reason" }]` with reason `missing_queue_url`.
- Ids that already have a queue URL still enqueue, including db-backed ids.
- Fixture pin under `tests/`. No secret values. No registry flip.

## Testable

- Env has an Amazon queue URL and no Kelkoo queue URL.
- Response is 200, `accepted: true`, `enqueued` contains `amazon`, `skipped` contains `{ "id": "kelkoo", "reason": "missing_queue_url" }`.
- A second case with every URL present returns `skipped` empty or absent of that id.

Refs #5058. Does not close #5058 (credentials and deploy stay there).
