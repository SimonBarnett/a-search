# FR-138: CDK Secrets Manager wiring for enabled provider credentials (amazon ebay rakuten cj awin impact)

**Repo:** SimonBarnett/a-search  
**Phase:** 3 - AWS installable release  
**Shape:** service (unchanged)

## Goal
Each enabled provider worker/onboarding gets its `.env.example` keys from a per-source secret (or one JSON secret with namespaced keys). Stay-dark providers omitted.

## Decision (LOCKED)

- Helper `wireProviderSecretEnv` in `cdk/lib/a-search-stack.js`
- Per-source secret via `-c <id>ProviderSecretArn` (`fromSecretCompleteArn`); JSON keys match credential env names from that provider's `.env.example`
- Enabled sources only: amazon, ebay, rakuten, cj, awin, impact (registry `enabled.live|sandbox`)
- Targets: each enabled worker Lambda; awin/impact onboarding share the same source secret
- Stay-dark providers omitted from `PROVIDER_CREDENTIAL_KEYS` (no secret construct / grant until an enable-provider FR)
- Plain public defaults (HOST/REGION/endpoints) stay as plain env via `applyProviderPlainDefaults`
- Pin: `tests/fr138-provider-secrets-cdk.test.js`; matrix section: `docs/secrets-matrix.md`

## Deliverables
- Pattern in CDK + docs/secrets-matrix.md section
- Pin: only enabled sources get secret grants

## Testable
- Synth + pin

## Out of scope
- Enabling Phase-2 dark providers
- Creating the secrets in AWS (ops)
