# FR-197: S3 customer tree bootstrap (widgetGuid)

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1185
**Clarified by:** FR-232 (#1346), FR-233 (#1347)

## Goal

On first sight of a host and first bind of a widgetGuid, create the customer tree under the physical prefix `{env}/x/` with `_host.json`, `widget.json`, empty `live.json`, and empty `searches.json`. No URI-slug folder.

## Deliverables

- `shared/widgets/widgetPath.js` - `physicalPrefix`, `hostDir`, `widgetDir`, `widgetFile`, `assertWidgetGuid`
- `shared/widgets/bootstrap.js` - `bootstrapHost`, `bootstrapWidget` (idempotent)
- Pin: `tests/components-piece-s3-bootstrap.test.js`

## Behaviour (LOCKED)

- First host sight: `{env}/x/{customerNumber}/_host.json` = `{ host, customerNumber, createdAt }`. Do not write `site.md` (agent-owned, FR-204).
- First widget bind: `{widgetGuid}/widget.json`, `{widgetGuid}/live.json` = `[]`, `{widgetGuid}/searches.json` = `{ "queries": [], "exclude": [] }`.
- Paths only via `widgetPath.js`. Physical prefix `{env}/x/` (FR-233).
- Second call is idempotent: existing `_host.json` / `widget.json` are not rewritten (no second event).

## Testable

- Pin: bootstrap creates expected keys; second call idempotent
- Fail-when: missing `live.json` after `bootstrapWidget`

## Out of scope

- Agent `site.md` content (FR-204)
- Widget JS / Parts / Click handlers
- `POST /widgets` mint (FR-232)
- URI-slug encoder (superseded)

## Historical note

The original FR text asked for a uri-slug encoder and `site.md` placeholders. Direction change 2026-10-10 (FR-232): widget identity is `widgetGuid`; this document reflects that lock.
