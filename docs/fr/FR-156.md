# FR-156: Stack stage/suffix parameter for parallel AWS deploys

**Repo:** SimonBarnett/a-search
**Phase:** 3b - AWS installable gap pass 2
**Shape:** service (unchanged)

## Goal
Single hard-coded `ASearchStack` / function names block staging a second install. Add optional stage suffix (e.g. `-dev`) for function/queue/bucket names via context.

## Deliverables
- Context `stage` / naming helper
- Pin: default names unchanged when stage empty; suffix applied when set
- deploy.md note

## Testable
- Synth twice with/without stage in unit test

## Out of scope
- Multi-region active-active

## Decision LOCKED

- Context: `-c stage=dev` (lowercase alphanumeric / hyphen segments)
- Helper: `cdk/lib/resolve-stage-suffix.js` (`resolveStageSuffix`, `withStageSuffix`, `resolveStackId`)
- Empty/unset stage: physical names and stack id unchanged (`ASearchStack`, `a-search-entry`, ...)
- Set stage: suffix `-<stage>` on functions, queues, DLQs, alarms, rules, API name, SNS topic; stack id `ASearchStack-<stage>`
- ResultsBucket remains CDK auto-named (unique per stack id)
- Pin: `tests/fr156-stage-suffix.test.js`
