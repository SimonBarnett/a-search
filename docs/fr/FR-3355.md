# FR-3355: in_ready EventBridge suffix targets IN/ folder

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (docs + classify helper)
**Issue:** #3355
**Depends on:** FR-3344 (#3344) IN/ folder layout

## Goal

FR-3344 stores inbound hits as `IN/{searchId}.json`. Agent-queue `in_ready` must fire on ObjectCreated under that IN/ folder only. The retired single-file inbound path must not enqueue. `IN/.processing/` must not enqueue.

## Decision (LOCKED)

- `in_ready` S3 key pattern: `{env}/x/{customerNumber}/{widgetGuid}/IN/{searchId}.json`
- Exclude: `IN/.processing/**`, non-json under IN/, agent outputs (`live.json`, `context.md`, `searches.json`, `site.md`, `top10.json`, `_agent/**`)
- Retired single-file inbound path under the widgetGuid folder does not classify as this event (FR-3344)
- Classify helper: `shared/widgets/agentEventClassify.js` (`isInReadyKey`, `classifyWidgetS3Key`)
- Enqueue Lambda (when present) must call classify before FIFO send (harvest lesson agentQueue.classify / FR MessageGroupId)
- CDK S3 notification rules (when added under #1343) must use the IN/ suffix (never the retired single-file name)
- Docs: `docs/agentic-searches-events.md` is the event-table home; living issue #1343 addendum is amended by this FR
