# FR-213: Click commission attribution uses cached partnerId

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1204
**Clarified by:** FR-232 (#1346), FR-248 (#1362), FR-250 (#1364)

## Goal

When `Customers.partnerId` is set (from optional Partner DNS TXT after Club approval), `/go` responses and click/audit records carry that `partnerId` so a digital agency that set up the host can claim commission. Missing `partnerId` is valid (self-serve club setup).

## Decision LOCKED

- `/go` reads `partnerId` from the cached Customers row (no DNS on every click after FR-200 cache).
- `recordClick` payload includes `partnerId` when present (null when absent) plus `widgetGuid` and `tenantId` (= `Customers.clubId`).
- Destination URL may also carry `partnerId` query for downstream tracking.
- Agency docs: add Partner TXT `a-search-partner=<partnerId>` alongside required Club TXT; Partner TXT alone never unlocks affiliate destinations (FR-200).
- Partner role gate (`Users.permissions` contains `partner` via `shared/identity/isPartner.js`) is FR-250; until that helper lands, TXT-derived `partnerId` is stored as FR-200 caches it.

## Deliverables

- Pin: `tests/fr213-partner-attribution.test.js`
- `shared/widgets/go.js` click record includes `partnerId` + `tenantId`
- This Decision LOCKED doc

## Testable

- Pin: approved + partnerId => destination returned and partnerId present on click record; DNS calls stay 0 when already cached
- Pin: approved + no partnerId => destination returned; partnerId null on record
- Fail-when: Partner TXT alone (no Club) ever yields affiliate destination

## Out of scope

- Payment/payout ledger UI
- Changing Club TXT approval rules (FR-200)
- Full FR-248 subIds / class stamping table
- FR-250 isPartner helper (separate FR)
