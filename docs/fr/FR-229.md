# FR-229: Shared login entry for merchant partner club roles

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged; login is delivery)
**Issue:** #1239

## Goal
One login stack serves merchant wizard, partner registration, and club entry; role attached after identity.

## Decision (LOCKED)

- One shared login stack: `shared/auth/loginEntry.js` mints sessions; thin HTTP in `entry/src/loginEntry.js`.
- UI entry: `components-piece/login/index.html` (`data-login-stack="shared"`). No separate merchant/partner/club login pages.
- Routes: `POST /auth/session` (mint shared session) and `GET /auth/redirect` (post-login path by intent/role).
- Post-login redirects: merchant -> merchant-wizard; partner -> partner-register; club -> club-entry.
- Same session object is valid for merchant, partner, and club intents after identity (email|phone|contact required; fail closed).
- Phase 5: no passwords (FR-225). Live OAuth adapters are FR-226+; email magic/OTP is FR-228.
- Fail-when: three divergent auth implementations (password stacks / duplicate session mints).
- Pin: `tests/fr229-shared-login-entry.test.js`. List `auth/` in `shared/package.json` files[] (FR-159).

## Deliverables
- Shared login route/component
- Post-login redirect by role/intent
- Pin that stacks are not duplicated

## Testable
- Same session valid on merchant and partner entry fixtures
- Fail-when: three divergent auth implementations

## Out of scope
- Full RBAC matrix
- Live OAuth token exchange
- Email magic/OTP productization (FR-228)
