# FR-3373: S3 host folder metadata, tags, and annotations

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service
**Issue:** #3373
**Depends on:** FR-197 / FR-232 / FR-233 (customerNumber widget tree), FR-200 (DNS TXT)

## Goal

When a host is first seen, attach S3 object metadata and tags to the host folder marker, and support larger annotation payloads for host and widgetGuid context.

## Decision (LOCKED)

- Physical tree stays `{env}/x/{customerNumber}/` (FR-197). Do not rename folders to the raw host URL.
- File-safe host representation is `safeHostFolderName(host)` (lowercase host; non `[a-z0-9.-]` -> `_`; no path separators). Stored as user-defined metadata `hostkey` for display/ops; Metadata `host` holds `normalizeHost(host)`.
- Zero-byte folder marker key: `{env}/x/{customerNumber}/` (trailing slash). Created once (idempotent IfNoneMatch / Head-then-Put).
- User-defined Metadata (immutable without copy): `userid` = creating user id (string). Also set `host`, `hostkey`, `customerNumber` at create time.
- Object tags (mutable, max 10): `hasdns` = `0`|`1`; `partnerid` = partner id from DNS or empty; `hasupg` = `0`|`1`. DNS check sets `hasdns=1` and may set `partnerid`; once `hasdns=1`, DNS TXT resolve must not repeat for that host folder (FR-200 cache still applies to Customers row).
- Annotations (up to 1 MiB UTF-8): portable sidecar objects until native S3 Annotations are wired fleet-wide:
  - Host: `{env}/x/{customerNumber}/_host.annotations.json` (agent website context)
  - Widget: `{env}/x/{customerNumber}/{widgetGuid}/_annotations.json` (extension-editable context)
- Helpers live in `shared/widgets/hostFolderMeta.js`. Callers inject `putObject` / `getObject` / `putObjectTagging` / `getObjectTagging` (no live AWS in unit tests).
- `bootstrapHost` calls `ensureHostFolderMarker` when `opts.s3` or `opts.putObject` is injected (FR #3490). Local-only bootstrap stays synchronous and still writes only `_host.json`.
- madeiradb remains read-only (FR-251).
