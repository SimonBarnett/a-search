# FR-238: WooCommerce shop connect via /wc-auth key generation

**Repo:** SimonBarnett/a-search
**Phase:** 5e - Merchant shops
**Issue:** #1352
**Status:** Decision LOCKED

## Goal
Merchant clicks Add shop -> WooCommerce, enters store URL, approves a-search in
WP admin through `/wc-auth/v1/authorize`, and Woo POSTs read-only REST keys to
our callback. Advanced paste of read-only keys is allowed as a fallback.

## Decision (LOCKED)

- Adapter: `shared/shops/adapters/woocommerce.js` registered as `woocommerce`.
- `POST /merchant/shops/connect { provider:"woocommerce", shopDomain }` requires
  **HTTPS** public host (reject `http://` and private/loopback IPs for SSRF),
  probes `GET /wp-json/wc/v3`, stores FR-216 `state`, returns `redirectUrl` =
  `{origin}/wc-auth/v1/authorize?...&scope=read&user_id={state}&callback_url=...`.
- Woo POSTs keys to `/merchant/shops/callback/woocommerce` with `user_id` =
  state. Verify `key_permissions == "read"`, probe
  `GET /wp-json/wc/v3/products?per_page=1`, upsert Shop `pending_payment`,
  vault-put `{ kind:"woocommerce_rest", consumerKey, consumerSecret, ... }` at
  `vault:woocommerce:{host}` (never log or echo keys).
- Advanced paste: same connect endpoint with `consumerKey` + `consumerSecret`
  (read only); validate + vault + Shop row in one response (`paste: true`).
- Bad domain / write keys / unknown nonce / failed key probe => **400**, no row.
- No uninstall webhook (Woo). Sync 401 (FR-240) => suspended(`auth`) later.
- Catalogue: `providers/local/woocommerce/src/catalog.js` accepts per-call
  `{ storeUrl|shopDomain, consumerKey, consumerSecret }` overrides.
- madeiradb read-only (FR-251). Shops in a_search (FR-235).
