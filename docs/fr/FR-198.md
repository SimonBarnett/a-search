# FR-198: Parts API GET /parts offset limit page

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1186
**Clarified by:** FR-232 (#1346), FR-197 (#1185), FR-196 (#1184)

## Goal

`GET /parts?host&widgetGuid&offset&n` returns `{ customerNumber, widgetGuid, layout, parts[], nextOffset }` from that widget's `live.json`. `uri` is optional diagnostics only.

## Deliverables

- `shared/widgets/parts.js` - `pageParts` (bind + FR-197 bootstrap + page)
- `entry/src/parts.js` - HTTP adapter; wired in `entry/src/index.js`
- CDK HTTP API `GET /parts` -> entry Lambda
- `shared/components/customers.js` `bindWidget` for first-sight bind
- Pin: `tests/components-piece-parts.test.js`

## Behaviour (LOCKED)

- Missing `widgetGuid` -> 400 `widget_guid_required`; malformed -> 400 `invalid_widget_guid`
- Bound to another host -> 403 `widget_host_mismatch`
- First request for an unbound GUID binds via Customers/Widgets store + FR-197 bootstrap
- Always pages that widget's `live.json`; **never** trims by upgrade tier
- Empty `live.json` -> `parts: []`, `nextOffset: null`

## Out of scope

- Click API (`GET /go`)
- Widget render / JS
- MSSQL adapter (MemoryCustomersStore for unit pins; FR-196 DDL present)

## Historical note

Original text used `host&uri`. Direction change 2026-10-10: `widgetGuid` is the key.
