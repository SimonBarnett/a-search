# FR-048: Deterministic exceptions must file a-search intake

## Goal
Any fatal/unhandled exception in deterministic a-search code (entry, workers,
maintainer, onboarding runners) must raise an issue through the bobiverse
intake webhook with `repo=SimonBarnett/a-search`.

## Deliverables
- `shared/intake/reportException.js` (or similar): POST
  `https://irc.ntsa.uk/bob/v1/intake` with `kind: issue`, title/body from error,
  `idempotency_key` from hash(code+message+route), source machine/function
- Wire top-level catch in entry handler, SQS worker handlers, maintainer
  schedule, onboarding runners
- Never include secrets/tokens in body (redact Authorization, connection strings)
- Offline: queue to local outbox path documented for Lambda /s optional no-op
  with metric when VPC blocks egress (document UNKNOWN deploy constraint)
- Docs in entry + shared skillbooks

## Testable
- Unit test: thrown Error → mock fetch/POST called once with repo a-search
- Dedup: same idempotency_key second call does not create duplicate payload shape
- Fail-when: handler catch only `console.log` with no intake call

## Out of scope
- Filing on every validation 400 (client errors); only unexpected/deterministic failures
