# FR-167: Enable provider kijiji (stay-dark -> registry enabled when credentials exist)

**Repo:** SimonBarnett/a-search
**Phase:** 4 - post-v0.1 enablement / hardiness
**Shape:** service (unchanged)

## Goal
Flip **only** `kelkoo` `enabled.live` / `enabled.sandbox` to true after credentials
exist in Secrets Manager, following `docs/phase3-enable-provider.md` (FR-126).
CDK must synthesise queues/workers for this id. All other stay-dark ids remain
false unless their own FR merged.

## Decision (LOCKED)

- `providers/registry.json`: `kelkoo.enabled.live=true` and
  `kelkoo.enabled.sandbox=true` only (siblings unchanged)
- `PROVIDER_CREDENTIAL_KEYS.kelkoo = ['KELKOO_API_KEY', 'KELKOO_PUBLISHER_ID']`
  in `cdk/lib/a-search-stack.js` (FR-138 pattern; no secrets in git)
- `PROVIDER_PLAIN_DEFAULTS.kelkoo.KELKOO_COUNTRY = 'uk'`
- Synth creates `a-search-kelkoo-{live,sandbox}` queues + worker Lambdas with
  Secrets Manager refs for the credential keys
- Selftest: fixture path in `providers/live/kelkoo` stays green
  (`kelkooSelftestProbe` + `offers-ok.json`); live smoke needs deploy-time secret
- Pin: `tests/fr167-enable-kelkoo.test.js`
- Docs: `docs/secrets-matrix.md`, `cdk/README.md`, `docs/phase2-providers.md`,
  `docs/phase3-enable-provider.md`

## Deliverables
- Registry enabled true for `kelkoo` only (both envs)
- Secret wiring for this source (pattern from FR-138)
- Pin: this id enabled; other Phase-2 ids unchanged unless already enabled by prior FR
- Selftest probe path documented green for this id (fixture)
