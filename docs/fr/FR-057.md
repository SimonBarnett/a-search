# FR-057: Created links use provider .env account + JWT userId tenant

## Goal
Every link a-search **creates** (affiliate / deep / tracking URLs written into
results JSON or signup/report payloads) must be built from that provider
folder’s `.env` account details, with the Bearer JWT `userId` claim as the
**tenant** stamp (clickRef / tracking param). Never hardcode publisher IDs or
reuse another tenant’s account.

## Deliverables
- Shared helper `shared/links/buildTrackedUrl.js` (or under `shared/` after
  FR-047): inputs `{ baseUrl or offer, source, userId, env, envVars }` → URL
- Account identifiers (publisher id, associate tag, network click-param names)
  read **only** from the provider’s process env / `.env` for that folder
  (e.g. `AWIN_PUBLISHER_ID`, `AMAZON_PARTNER_TAG`, …) — documented in each
  `.env.example`
- Tenant: always `String(jwtUserId)`; reject empty; never take tenant from
  request body
- Wire amazon/ebay/rakuten/cj/awin/impact normalize or link-build paths so
  `product.url` (and any `trackingUrl`) go through the helper when a-search
  creates/rewrites the link
- Docs: `docs/tracked-links.md` + update `a-search-endpoint` and per-provider
  skillbooks; add Success row in vision via follow-on or this PR if small
- Hostile pin: helper unit tests + source scan that builders do not embed
  literal publisher ids

## Testable
- Unit: same offer + two userIds → URLs differ by tenant stamp; same userId +
  two publisher env values → account segment differs
- Missing required .env account key → clear error (no silent untracked link)
- Body `userId` ignored for tenant (JWT only)
- Fail-when: results still emit raw DetailPageURL / feed URL with no tenant
  stamp when a tracked link is required for that source

## Out of scope
- Changing JWT issuer; Club Madeira UI; inventing network APIs
