# FR-034: Resolve queueEnv to live/sandbox queue URL

## Goal
Registry `queueEnv` (e.g. `SQS_AMAZON_URL`) must resolve to the correct
live vs sandbox queue URL without inventing a second registry schema break.

## Deliverables
- Helper e.g. `providers/resolveQueueUrl.js`: given `queueEnv` + `env`,
  prefer `SQS_<SOURCE>_<ENV>_URL` then fall back to `SQS_<SOURCE>_URL` if set
  only for that single env deploy, else error
- Align CDK outputs / entry env docs with the chosen convention
- Update `docs/environments.md` + add-source checklist

## Testable
- Unit tests: live picks `*_LIVE_URL`; sandbox picks `*_SANDBOX_URL`;
  missing URL to clear error (no silent noop enqueue for that source)
- Fail-when: entry still documents only `SQS_AMAZON_URL` while CDK only
  emits `SQS_AMAZON_LIVE_URL` with no resolver

## Out of scope
- Implementing SendMessage itself (FR-032) beyond calling the resolver
