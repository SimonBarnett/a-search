# FR-3344: IN must be a folder, not a single in.json

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #3344

## Goal

Many searches push normalised hits to S3. Do not merge them into one `in.json`. Use an `IN/` folder with one file per search.

## Decision (LOCKED)

- Replace widget-tree `in.json` with `IN/` directory.
- Writer: `writeInSearchFile({ root, env, customerNumber, widgetGuid, searchId, parts })` -> `IN/{searchId}.json`.
- Item shape unchanged: `{ id, title, price, currency, merchant, image, url, seenAt }` (plus optional score).
- Agent ingest (FR-206): claim all ready `IN/*.json` into `IN/.processing/`, merge into `live.json`, delete processing files.
- Event `in_ready` (FR-233 / #1343): ObjectCreated under `{customerNumber}/{widgetGuid}/IN/` (json files). Do not fire on `IN/.processing/` writes or agent `live.json` writes.
- Legacy single `in.json` is not written by new code.
