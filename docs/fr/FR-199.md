# FR-199: Click API GET /go approved path

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1187
**Clarified by:** FR-232 (#1346), FR-248 (#1362), FR-234 (#1348)

## Goal

Approved host `GET /go?host&widgetGuid&part&cid` returns `{ url, clickId }` from that widget's `live.json` only.

## Deliverables

- `shared/widgets/go.js` - `resolveGo` (GUID + host bind + approval + part lookup + stamp)
- `entry/src/go.js` - HTTP adapter; wired in `entry/src/index.js`
- CDK HTTP API `GET /go` -> entry Lambda
- Pin: `tests/components-piece-go.test.js`

## Behaviour (LOCKED)

- Validate `widgetGuid`; bound host mismatch -> 403 `widget_host_mismatch` (no URL)
- Host not approved -> 403 `host_not_approved` (FR-200 owns signup URL path)
- Part missing in that widget's `live.json` -> 404 `part_not_found`
- Never search other widgets; same `partNumber` in two widgets resolves to each widget's own URL
- `class=merchant` -> plain destination URL; affiliate/provider without tenant/clubId -> 503 `tracking_unavailable`
- Optional `cid`; server generates clickId when missing; injectable `recordClick` fire-and-forget (FR-234)
- Prefetch / HEAD do not record part clicks

## Out of scope

- DNS TXT / signup redirect body (FR-200)
- Full per-source affiliate param table (FR-248 detail; lite stamp here)
- Widget JS / Chrome extension UI

## Historical note

Original text used `host&uri`. Direction change 2026-10-10: `widgetGuid` is the key.
