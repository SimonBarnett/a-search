# FR-234: Widget events, stats.json, extension stats API

**Repo:** SimonBarnett/a-search
**Issue:** #1348
**Phase:** 5d - ComponentsPiece

## Decision (LOCKED)

- Public `POST /w/events` (beacon, text/plain JSON) validates then applies/enqueues.
  Always `204` for well-formed input (drops are silent + metric reason).
- `fullTier` ranking thresholds from the first draft are **withdrawn** (Simon):
  agent judges from `stats.json`; `exclude[]` always wins; never empty a widget
  for stats alone.
- Storage in `a_search` / `a_search_sandbox` only: `WidgetStatsDaily`,
  `WidgetEventDedupe` (FR-251). No IP, cookie, UA, or user id columns.
- Stripe/product split: `widget_upgrade` is distinct from `merchant_shop` (FR-239).
- Hourly rollup writes `stats.json` under the widget and host folders and must
  **not** enqueue an agent job (`stats_changed` is not a #1343 trigger).
- Server `/go` records clicks with `cid` (same clickId dedupe as client events).

## Owners

- Ingest: `shared/events/ingestBatch.js`, `entry/src/widgetEvents.js`
- Store: `shared/events/memoryWidgetStatsStore.js`, `db/migrations/016_WidgetStats.sql`

- Widget emitter: `widget/a-search-widget.js` (`createEventBatcher`, `cid` on `/go`)
- CDK: `a-search-widget-events` queue + DLQ + aggregator + hourly schedule
