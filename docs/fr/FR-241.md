# FR-241: Unpaid shops never download; hard-delete after 2 unpaid periods

**Repo:** SimonBarnett/a-search
**Phase:** 5e - Merchant shops
**Issue:** #1355
**Status:** Decision LOCKED

## Goal

Do not download shops whose subscription is unpaid. After 2 consecutive unpaid
billing periods, hard-delete that shop's a-search data. Merchant login is kept.

## Decision (LOCKED)

Simon 14:11 / 14:35-14:49 / 15:27 BST (issue updates win over earlier drafts).

- **Paid for download (FR-240):** `subscriptionStatus === active` only.
  `trialing`, `past_due`, and all other statuses are unpaid for enqueue/consumer.
- **Enqueue + consumer gates:** go-live and weekly roll skip unpaid
  (`ShopSyncSkipped{reason:"unpaid"}`). Consumer re-checks before any provider
  call; sets `lastSyncResult=skipped_unpaid`; does not advance NextCheck.
- **past_due serving:** already-imported parts keep being served during
  `past_due`. Downloads stop immediately.
- **Unpaid period:** a billing period whose `subscription_cycle` invoice is not
  `paid` by `period_end`. Paid invoice resets `consecutiveUnpaidPeriods` to 0.
- **Scope = per shop.** Other paid shops of the same merchant keep syncing.
  Merchant account / JWT login is never removed for non-payment.
- **Hard-delete (no 30-day soft retain of shop data):** after counter >= 2 and
  N2 was sent at least 7 days earlier:
  1. Cancel that shop's Stripe subscription (no proration/refund).
  2. Mark remaining open invoices uncollectible (never chase).
  3. Revoke provider tokens where an API exists; delete Secrets Manager secret
     (`ForceDeleteWithoutRecovery`).
  4. Hard-delete `a_search.dbo.Parts` for that FeedKey and delete the
     `PartFeedKeys` row.
  5. Shop status `cancelled` with `suspendReason=removed`.
- **Notices (SMS + email if on file, FR-228):**
  - N1 on first unpaid period: "payment failed; downloads paused".
  - N2 >= 7 days before projected second period_end: shop data for {domain}
    will be deleted on {date} unless payment is made; login to re-subscribe.
  - N3 on deletion.
  - Hard-delete must not run until N2 is at least 7 days old (postpone if needed).
- **Re-subscribe:** merchant logs in, re-verifies Stripe, reconnects the shop
  (new Shop row + subscription) -> fresh FR-240 full import. Old invoices stay
  uncollectible; no settle required.
- **DB:** all writes in `a_search` / `a_search_sandbox` (FR-251). madeiradb
  read-only; never delete madeiradb Users for this flow.
- **Modules:** `shared/shops/unpaid.js` (+ registry unpaid fields, shopSync
  hardDeleteFeed/deleteKey). Daily tick: `runMerchantDunning`.
