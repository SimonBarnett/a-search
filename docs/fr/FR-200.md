# FR-200: Click API dual DNS TXT gate (Club required, Partner optional)

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1188

## Goal
Unapproved hosts: require **Club** DNS TXT (club id) before returning affiliate destinations. **Partner** DNS TXT is optional; when present, store partnerId so a digital agency can claim commission. No Club TXT => signup URL only (never affiliate target). Cache DNS results on the Customers row so lookups are not repeated every click.

## Decision (LOCKED)

- TXT lookup is on the **host apex** via `dns.resolveTxt(host)` (injectable in tests).
- LOCKED TXT value prefixes (ASCII, case-insensitive prefix match):
  - `a-search-club=<clubId>` (required to approve / enable extension)
  - `a-search-partner=<partnerId>` (optional commission claim)
- Partner TXT alone never unlocks destinations and never enables the extension.
- partnerId is persisted only when clubId is present.
- Signup URL from env `A_SEARCH_SIGNUP_URL` (no secret). Unapproved + no Club => HTTP 200 `{ url: <signup> }` only.
- Shared module: `shared/dns/hostTxtStatus.js` returns `{ clubId, partnerId, checkedAt }` and updates Customers cache (`approved`, `clubId`, `partnerId`, `dnsCheckedAt`).
- Negative cache TTL: `EXT_STATUS_NEG_TTL_S` (default 600). Positive (approved) cache is sticky until force refresh.
- `GET /ext/status?host` uses the same module; `enabled` is true only when Club TXT is present.
- `/ext/status` then `/go` on the same host shares one DNS query when cache is warm.
- Keys: `host + widgetGuid + part` (FR-232). Writes only in `a_search` / `a_search_sandbox` (FR-251).

## Deliverables
- Stub-able dual TXT lookup: Club record + optional Partner record
- Club TXT absent => `{ url: signup }` only; never affiliate destination
- Club TXT present => mark approved, persist clubId, return destination from live.json
- Partner TXT present => persist partnerId (commission); Partner TXT alone does not approve
- Signup URL config (no secret)
- Cache timestamps for club (and partner when seen)
- `shared/dns/hostTxtStatus.js` + `GET /ext/status`

## Testable
- go pin: no Club TXT => signup only (even if Partner TXT present)
- go pin: Club TXT only => approve + destination; partnerId null/empty
- go pin: Club + Partner TXT => approve + destination + partnerId set
- second click after approve: Club DNS call count stays 1 (cached)
- `/ext/status` then `/go` => one DNS query total

## Out of scope
- Widget embed
- Agent
- Chrome extension UI (#1344 consumes `/ext/status`)
