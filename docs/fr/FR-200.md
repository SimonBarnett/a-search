# FR-200: Click API dual DNS TXT gate (Club required, Partner optional)

**Repo:** SimonBarnett/a-search
**Phase:** 5 - ComponentsPiece
**Shape:** service (unchanged)
**Issue:** #1188

## Goal
Unapproved hosts: require **Club** DNS TXT (club id) before returning affiliate destinations. **Partner** DNS TXT is optional; when present, store partnerId so a digital agency can claim commission. No Club TXT => signup URL only (never affiliate target). Cache DNS results on the Customers row so lookups are not repeated every click.

## Deliverables
- Stub-able dual TXT lookup: Club record + optional Partner record
- Club TXT absent => `{ url: signup }` only; never affiliate destination
- Club TXT present => mark approved, persist clubId, return destination from live.json
- Partner TXT present => persist partnerId (commission); Partner TXT alone does not approve
- Signup URL config (no secret)
- Cache timestamps for club (and partner when seen)

## Testable
- go pin: no Club TXT => signup only (even if Partner TXT present)
- go pin: Club TXT only => approve + destination; partnerId null/empty
- go pin: Club + Partner TXT => approve + destination + partnerId set
- second click after approve: Club DNS call count stays 1 (cached)

## Out of scope
- Widget embed
- Agent
- Exact public TXT name strings (document as LOCKED names in docs when chosen; values are clubId/partnerId)
