# FR #5326

GitHub: https://github.com/SimonBarnett/a-search/issues/5326

## Goal

Post-deploy smoke treats Amazon as a queued source on the accept body.

## Deliverables

- `scripts/smoke-deploy.js` (or the unit that tests `assertSearchAccept`) requires `enqueued` to contain `amazon` when `enqueued` is present.
- `skipped` may list other ids (for example kelkoo with `missing_queue_url`) without failing the accept.
- Unit fixture only. Do not call AWS from the test.

## Testable

- Fixture `{ accepted: true, searchId: "srch_smoke", enqueued: ["amazon","ebay"], skipped: [{ id: "kelkoo", reason: "missing_queue_url" }] }` passes.
- The same body with `amazon` absent fails the assert.
- A body with no `enqueued` field still passes the older accepted/searchId checks (catalog path before the skip field exists).

Depends on the catalog skip issue for a live deploy where Kelkoo has no queue URL. The unit fixture does not.
